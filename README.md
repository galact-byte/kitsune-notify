# 稻荷神社 回复邮件提醒

[![License: MIT](https://img.shields.io/badge/License-MIT-yellow.svg)](LICENSE)

当你在 [kitsune.ee](https://kitsune.ee/)（Discuz 论坛「稻荷神社」）的帖子被别人**回复**时，自动发一封邮件到你的邮箱。

仓库：https://github.com/galact-byte/kitsune-notify

两半组成：

| 文件 | 跑在哪 | 做什么 |
|---|---|---|
| `kitsune-notify.user.js` | 浏览器（Tampermonkey） | 轮询论坛提醒页、去重、触发发信 |
| `Code.gs` | Google 服务器（Apps Script） | 收到 POST 后用你的 Gmail 发信 |

密钥不写进代码：URL / TOKEN / 收件邮箱存在浏览器本地（`GM_setValue`）。

## 它能做到 / 做不到

- ✅ **开着浏览器、且论坛标签页在**时，每 5 分钟检查一次，有新回复就发邮件。
- ✅ **首次装好**会把当前已有的历史提醒设为基线（不发），只发之后新出现的——避免一装好就被老回复淹没。
- ✅ **补发**：关机/关浏览器期间累积的提醒，下次一开浏览器（挂着论坛标签页）会被补发。
- ✅ 发信走你自己的 Gmail（部署在 Google 服务器，发信不需要你开电脑）。
- ❌ **做不到关机时段实时推**——油猴脚本只在浏览器开着时才跑。这是唯一硬限制。

> 建议：把 `https://kitsune.ee/forum.php` 设成一个**钉住 (pin)** 的标签页常驻后台，检查就一直在跑。

当前脚本版本：**v1.5.3**。

## 一、部署发信端（Apps Script，约 5 分钟，只做一次）

1. 打开 https://script.google.com/ ，点「新建项目」。
2. 把项目里默认的 `Code.gs` 内容**全部删掉**，粘贴本仓库 `Code.gs` 的全部内容。
3. 改开头两个值：
   - `TO_EMAIL`：改成你要收提醒的邮箱（不一定是 Gmail）。
   - `TOKEN`：把占位符换成你自己的随机口令（字母数字即可）。**必须和稍后油猴面板里填的 TOKEN 完全一致。**
4. 先验证发信权限：顶部函数下拉选 `sendTestEmail` → 点「运行」。第一次会弹授权：
   - 选你的 Google 账号 → 「高级」→「转至（不安全）」→ 允许发送 Gmail。
   - 运行成功后，去 `TO_EMAIL` 邮箱确认收到「部署测试」邮件。
5. 部署为 Web 应用：右上「部署」→「新建部署」→ 类型选「**网络应用 / Web app**」：
   - 执行身份：**我（你自己）**
   - 谁可以访问：**任何人 / Anyone**
   - 点「部署」，复制那条以 **`/exec` 结尾**的网页应用 URL。

> 记住这条 `/exec` URL 和你的 `TOKEN`，下一步要填进油猴面板。

改过 `Code.gs` 之后必须再「部署」→「管理部署」→ 编辑 → **新版本**，旧 `/exec` 不会自动吃到新代码。

## 二、装油猴脚本

1. 浏览器装 [Tampermonkey](https://www.tampermonkey.net/)（若还没装）。
2. Tampermonkey → 管理面板 →「+」新建脚本，把本仓库 `kitsune-notify.user.js` 全部内容粘贴进去覆盖，保存。
3. **密钥不用改代码**：登录 kitsune.ee 开一个论坛页，点页面**右下角朱红圆形图标**打开居中管理面板，填：
   - **部署 URL**：上一步那条 `/exec` URL。
   - **TOKEN**：和 `Code.gs` 里保持一致。
   - **收件邮箱**：提醒发到哪。
   - （可选）勾选「也被 @ 时发邮件」。默认关。
4. 点「保存」。三项存在浏览器本地，不写进代码、不进 git。

油猴菜单里的「打开稻荷提醒面板」只是备用入口，主入口是右下角图标。

---

## 三、验证闭环（重要，别跳过）

1. 登录 kitsune.ee，随便开一个论坛页面（脚本约 8 秒后会自动跑首次基线）。右下角应出现朱红圆形图标；未配置时图标带一圈提示色。
2. 点该图标打开面板。提示出现在**页面上方居中**，不挡图标。
3. 按这个顺序点：

   | 按钮 | 期望 |
   |---|---|
   | **保存** | 上方提示已保存 |
   | **发送测试邮件** | 上方提示「已发送」或「网关超时、多半已发出」→ **先查收，不要立刻再点** |
   | **立即检查** | 首次只做基线、不发信，这是正常的 |
   | **清空去重** → 再 **立即检查** | 会把当前提醒里的真实回复发一封真邮件过来 |

「发送测试邮件」能进邮箱 = 整条链路（浏览器 → Apps Script → 邮箱）通了。这是最关键的一步。

## 常见问题

- **点测试邮件报错 / 收不到**：面板里 Apps Script URL 没填对（必须 `/exec` 结尾），或部署的「谁可以访问」不是「任何人」，或两边 `TOKEN` 不一致。改过 `Code.gs` 后要新建部署版本。
- **提示网关超时 / HTTP 408，但邮箱其实收到了**：Apps Script 冷启动时网关会先超时，邮件往往已经发出。脚本会把 408/502/504 当成「可能已发出」，按钮冷却约 45 秒。请先查收，不要立刻再点，否则会收到第二封。
- **立即检查提示拉不到提醒页**：请确认当前标签已登录 kitsune.ee。脚本先走页面自己的 `fetch`（带登录 cookie），失败再换油猴通道。
- **立即检查误报「论坛拦截」**：旧版会把 Discuz 每页 JS 里的 `attackevasive = '0'`、或语言包里的「抱歉」当成拦截。v1.5.3 只认正文「访问过于频繁 / 刷新过于频繁」。
- **日志在哪看**：论坛页面按 F12 → Console，脚本会打 `[稻荷提醒]` 开头的日志。
- **会不会重复发**：不会。按 Discuz 的 `notice` 唯一 ID 去重，发过的不再发；多个论坛标签页也只发一次。
- **红点会不会被清**：脚本后台读取提醒页会把该类型的站内红点标记为已读（Discuz 机制，一打开提醒页就会清）——但你会收到邮件，不影响回帖。
- **改轮询间隔**：脚本里 `POLL_INTERVAL_MIN`（默认 5 分钟）。
- **想连「被@」也提醒**：默认只跟回复（`type=post`）。在面板勾选「也被 @ 时发邮件」。开启后会多拉一个 @提醒页，因此也会清掉站内 @红点。评分等其他类型未启用。
- **一次性涌入 >30 条回复**：提醒页单页 30 条，离线期间超过 30 条的最旧部分可能漏接（极端情况）。
- **连点「立即检查」进不去论坛**：Discuz 有 IP 级 flood 防御。脚本已加 30 秒手动节流；多提醒页串行拉取、页间隔 3 秒。被拦了等 5–10 分钟自解。
