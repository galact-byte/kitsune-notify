# 稻荷神社 回复邮件提醒 · 接线说明

当你在 kitsune.ee（Discuz 论坛）的帖子/回复被别人**回复**时，自动发一封邮件到你邮箱。（跟踪的是 Discuz 提醒里的“回复”类型 type=post。）

## 它能做到 / 做不到

- ✅ 你**开着浏览器、且论坛标签页在**时，每 5 分钟检查一次，有新回复就发邮件。
- ℹ️ **首次装好时**会把当前已有的历史提醒设为“基线”（不发），只发之后新出现的——避免一装好就被一堆老回复淹没。
- ✅ **补发**：关机/关浏览器期间累积的提醒，下次你一开浏览器（挂着论坛标签页）会被补发，不会漏。
- ✅ 发信走你自己的 Gmail（Apps Script 部署在 Google 服务器，发信不需要你开电脑）。
- ❌ **做不到关机时段实时推**——油猴脚本只在浏览器开着时才跑。这是唯一硬限制。

> 建议：把 `https://kitsune.ee/forum.php` 设成一个**钉住(pin)的标签页**常驻后台，检查就一直在跑。

---

## 一、部署发信端（Apps Script，约 5 分钟，只做一次）

1. 打开 https://script.google.com/ ，点「新建项目」。
2. 把项目里默认的 `Code.gs` 内容**全部删掉**，粘贴本目录 `Code.gs` 的全部内容。
3. 改开头两个值：
   - `TO_EMAIL`：改成你要收提醒的邮箱。
   - `TOKEN`：默认已给了一个随机值，可不改；若改，要和油猴脚本里的 `TOKEN` **保持一致**。
4. 先验证发信权限：顶部函数下拉选 `sendTestEmail` → 点「运行」。第一次会弹授权：
   - 选你的 Google 账号 → 「高级」→「转至（不安全）」→ 允许发送 Gmail。
   - 运行成功后，去 `TO_EMAIL` 邮箱确认收到「部署测试」邮件。
5. 部署为 Web 应用：右上「部署」→「新建部署」→ 类型选「**网络应用 / Web app**」：
   - 执行身份：**我（你自己）**
   - 谁可以访问：**任何人 / Anyone**
   - 点「部署」，复制那条以 **`/exec` 结尾**的**网页应用 URL**。

> 记住这条 `/exec` URL 和你的 `TOKEN`，下一步要填进油猴脚本。

## 二、装油猴脚本

1. 浏览器装 Tampermonkey（篡改猴）扩展（若还没装）。
2. Tampermonkey → 管理面板 →「+」新建脚本，把本目录 `kitsune-notify.user.js` 全部内容粘贴进去覆盖，保存。
3. **密钥不用改代码**：登录 kitsune.ee 开一个论坛页，点 Tampermonkey 图标 →「⚙ 设置（URL / TOKEN / 邮箱）」，依次填：
   - **Apps Script URL**：上一步那条 `/exec` URL。
   - **TOKEN**：和 `Code.gs` 里保持一致。
   - **收件邮箱**：提醒发到哪。
   三项存在浏览器本地(GM_setValue)，不写进代码、不进 git。

## 三、验证闭环（重要，别跳过）

1. 登录 kitsune.ee，随便开一个论坛页面（脚本会在 8 秒后自动跑首次基线）。
2. 点 Tampermonkey 图标 → 会看到下列菜单命令：
   - **⚙ 设置**：填/改 URL / TOKEN / 收件邮箱（未配置时先点这个）。
   - **① 发送测试邮件**：点它 → 弹「已发送」→ 去邮箱确认收到。**收到 = 整条链路（浏览器→Apps Script→邮箱）通了。**这是最关键的一步验证。
   - **② 立即检查一次**：不用等 5 分钟，立刻拉一次提醒。
   - **③ 重发当前提醒**：清空去重。
3. 想用**真实回复**验证格式对不对：先点「③ 重发当前提醒」再点「② 立即检查一次」→ 会把你当前提醒里的真实回复（含帖子链接）发一封真邮件过来。

> 注：刚装好时直接点「②」不会发邮件（因为首次在做基线），这是正常的。用「③→②」就能看到真实邮件。

## 常见问题

- **点测试邮件报错 / 收不到**：多半是「⚙ 设置」里 Apps Script URL 没填对（必须 `/exec` 结尾），或 Apps Script 部署的「谁可以访问」不是「任何人」，或两边 `TOKEN` 不一致。
- **日志在哪看**：论坛页面按 F12 → Console，脚本会打 `[稻荷提醒]` 开头的日志。
- **会不会重复发**：不会。按 Discuz 的 `notice` 唯一 ID 去重，发过的不再发；多个论坛标签页也只发一次。
- **红点会不会被清**：脚本后台读取提醒页会把该类型的站内红点标记为已读（Discuz 机制，一打开提醒页就会清）——但你会收到邮件，不影响你回帖。若这点介意，告诉我。
- **改轮询间隔**：脚本里 `POLL_INTERVAL_MIN`。
- **想连 @/评分也提醒**：默认只跟回复（type=post）。要加“被@”（type=at）等，告诉我，再加一条轮询即可。
- **一次性涌入 >30 条回复**：提醒页单页 30 条，离线期间超过 30 条的最旧部分可能漏接（极端情况）。
